# Stage Map Editor 사용 및 검증

맵과 웨이브 연결은 `Tools > Stage Map Editor`에서 설정합니다. 이 창에 저장한 맵별 설정을 전투 진입, WaveLoader와 StageMapLoader가 함께 읽습니다.

1. 편집할 Tilemap을 선택합니다. 처음 사용하는 맵이면 **이 Tilemap 등록**을 누릅니다.
2. **입장 버튼**에 이 맵을 여는 WaveSetter를 등록합니다. 버튼의 On Click에는 `SelectSkillByIndex`를 연결하고, On Stage Entered에는 화면 활성화 이벤트를 넣습니다.
3. **등록된 몬스터**에 MonsterData를 추가합니다. ID는 맵 안에서 고유해야 하고 프리팹 루트에 MonsterBase가 있어야 합니다.
4. 웨이브 슬롯에 기존 WaveData를 넣거나 **새 WaveData 추가**로 생성합니다. 위에서 아래 순서로 실행하며 `↑`/`↓`로 순서를 바꿉니다. 빈 슬롯은 전투 진입 전에 채웁니다.
5. Monster 탭에서 몬스터를 선택하고 타일판에 좌클릭/드래그로 배치합니다. 우클릭/드래그는 삭제합니다. **현재 WaveData 저장**으로 배치를 저장합니다.
6. **맵 설정 저장 (Scene)**으로 버튼, 몬스터 목록과 웨이브 순서를 저장합니다. WaveData를 여러 맵/슬롯에서 공유하면 몬스터 배치도 공유됩니다.

## 맵 설정과 클리어 기록

- **이 맵 설정 삭제**는 선택한 맵의 설정만 제거합니다. 다른 맵의 연결과 클리어 ID는 바뀌지 않으며 WaveData 에셋은 유지됩니다. Ctrl+Z로 설정을 복원합니다.
- 기본 **클리어 기록 ID**는 맵별 고유 번호입니다. 저장 파일에 사용한 ID는 다른 스테이지에 재사용하지 마세요.
- 같은 맵을 서로 다른 스테이지 버튼이 사용할 때는 각 버튼의 **Clear Id**를 지정합니다. `-1`이면 맵의 기본 ID를 사용합니다. 튜토리얼의 공유 맵 버튼은 기존 0~29 기록을 각각 유지합니다.
- 버튼별 입장 조건은 **StageButtonImageController > Requred Progress**로 설정합니다. 진행도는 해당 값 이상이어야 하며 0이면 제한이 없습니다.
- WaveManager 인스펙터는 등록 개수와 맵에디터 열기 버튼을 제공합니다. WaveLoader는 별도 몬스터 목록 없이 선택한 맵의 등록 목록을 사용합니다.
- 등록되지 않은 맵/버튼, 중복된 맵/버튼, 미등록 또는 중복 몬스터 ID를 다른 설정으로 대체하지 않습니다. 잘못된 웨이브는 부분 생성되거나 실행 순서가 넘어가지 않습니다.

## 장애물과 필드

맵에디터에서 **Stage Map Data**를 지정하거나 **Stage Map Data 생성**을 누릅니다. Obstacle / Field Effect 탭으로 배치하고 **장애물/필드 데이터 저장**과 **맵 설정 저장 (Scene)**을 누릅니다. 이동을 막는 장애물은 몬스터 배치와 겹칠 수 없습니다. 전투 진입 시 선택한 맵의 데이터로 장애물과 기본 필드 효과를 생성하고 퇴장 시 정리합니다. None/Custom은 전투 효과를 적용하지 않습니다.

Scene View에서도 배치하려면 **Scene View에서도 배치**를 켭니다. 각 탭의 우클릭은 해당 종류만 지우며 Erase 탭은 선택한 칸의 모든 종류를 지웁니다.

## 여러 칸을 차지하는 몬스터

- MonsterData의 **Footprint Size**로 가로·세로 칸 수를 지정합니다. 기존 몬스터는 `1×1`이며, `2×2`는 네 칸을 차지하는 몬스터 한 마리입니다. 배치 좌표는 왼쪽 아래 기준 칸이고 몸은 오른쪽·위쪽으로 확장됩니다. **Fit Sprite To Footprint**를 켜면 스프라이트 크기도 해당 영역에 맞춥니다.
- MonsterData의 **Has Shield**를 켜면 점유한 칸마다 실드가 하나씩 생깁니다. 실드는 해당 칸에 들어온 양수 피해 한 번을 전부 막고 사라지며, 다음 공격부터 그 칸이 본체 HP 피해를 받습니다. 데미지가 3이어도 실드와 HP를 동시에 깎지 않습니다. 기존 몬스터는 기본적으로 실드가 없습니다.
- `Assets/1.Datas/Original/ScriptableObjects/Enemy/LargeMonster_2x2.asset`은 ID `1000`, 이름 **중장갑 거대병**, HP `8`, 칸별 실드 `4개`인 `2×2` 샘플입니다. 기존 Enemy1 그림을 사용하는 전용 프리팹과 연결되어 있습니다. 맵에디터의 **등록된 몬스터**에 이 에셋을 추가한 뒤 팔레트에서 선택해 배치하세요. 5스테이지의 기존 배치에도 등록되어 있습니다.
- 타일판과 Scene View에서 모든 점유 칸을 표시합니다. 몸의 어느 칸을 우클릭해도 몬스터 전체를 지우며 Undo로 복원합니다. 모든 칸에 타일이 있어야 하고 다른 몬스터나 이동을 막는 장애물과 겹칠 수 없습니다. 기준 칸 하나만 WaveData에 저장합니다.
- 몸의 어느 칸을 공격해도 같은 HP를 사용합니다. 한 스킬은 닿은 칸의 실드를 각각 제거하고, 공격 시작 시 실드가 없던 칸 중 가장 높은 타일 데미지를 본체에 한 번 적용합니다. 동일 칸의 중복 판정으로 실드를 제거한 직후 HP까지 깎지 않으며, 적중·처치 보상도 한 번 계산합니다. 실드만 제거한 공격은 백하린의 생존 적 추가 공격을 발동시키지 않습니다.
- 밀치기는 몸 전체가 들어갈 공간까지 이동하며, 각 몸 칸의 남은 실드와 제거된 실드 상태가 함께 이동합니다. 실패한 배치와 같은 위치의 재배치는 실드를 재생성하지 않습니다. 사망·비활성화 시 점유와 실드를 정리하고, 새로 생성·초기화한 몬스터는 데이터 설정대로 실드를 복원합니다. 실드 상태는 개별 몬스터가 관리하며 MonsterData 에셋이나 다른 몬스터를 바꾸지 않습니다.
- 자동 공격과 화상은 시전자와 가장 가까운 몸의 칸을 공격하며, 류해랑은 이동한 아군을 기준으로 칸을 선택합니다. 도예화는 바로 앞의 몸 칸, 조율하의 폭탄은 반경에 닿은 모든 몸 칸을 공격합니다. 화염·전기 필드는 닿은 칸마다 실드를 검사하고, 노출된 칸의 가장 큰 피해를 종류별로 한 번 적용합니다. 피해를 먼저 처리한 뒤 바람으로 이동하므로 필드가 맞은 몸 칸이 바뀌지 않습니다. 얼음·바람·대지·암흑의 제어는 실드 유무와 관계없이 적용하고, 대지·암흑 피해 감소는 큰 값 하나를 사용합니다.
- 대상 정보창은 본체 HP, 점유 크기, 남은 실드 칸 수와 현재 커서 칸의 실드 유무를 표시합니다. 실드 손실과 이동 후에도 정보를 갱신합니다. 맵 에디터 팔레트에도 칸별 실드 설정을 표시합니다.

## 전투 후 시나리오와 스킵

- 맵에디터의 **전투 후 시나리오**에 대사 오브젝트와 `next` 버튼을 포함한 루트 GameObject를 지정합니다.
- 클리어 기록과 자동 저장, 전투 유닛/맵 정리를 마친 뒤 설정한 시나리오를 엽니다. 시나리오가 미지정이거나 패배/중도 퇴장한 경우 월드로 복귀합니다.
- Dialog1~Dialog5는 마지막 대사 뒤 클릭 시 스킵 버튼의 **On Click**에 연결된 함수들을 그대로 한 번 실행합니다. **Skip Button**을 직접 지정할 수 있고, 미지정 시 같은 시나리오의 `next` 버튼을 찾습니다. 버튼의 표시 상태와 클릭 이벤트는 인스펙터 설정을 유지합니다. 다시 열면 첫 대사부터 시작하며, 빈 대사도 대화창 클릭 또는 기존 스킵 버튼으로 종료할 수 있습니다.
- 전투 전/후 시나리오 모두 기존 스킵 버튼의 함수 연결을 그대로 사용합니다. 전투 후 시나리오의 이동 대상도 버튼의 **On Click**에서 설정하세요. 대사/UI 직렬화 필드명은 유지합니다.

## 전투 표시

- `S_Stage/Top/StageInfo/wave`는 선택한 맵의 웨이브 목록에서 현재 진행 중인 순번을 1부터 표시합니다. 같은 WaveData를 여러 번 넣어도 실행 중인 슬롯의 순번을 표시하고, 로드 실패 시 증가하지 않습니다.
- `enemy`는 살아 있고 활성화된 몬스터 수입니다. 대형 몬스터도 한 마리로 계산하고 직접 공격·필드 피해로 처치되면 갱신합니다.
- 화염은 빨강, 얼음은 파랑, 전기는 노랑, 바람은 초록, 대지는 갈색, 암흑은 보라색입니다. 사거리/범위/이동 미리보기 중에도 필드의 색을 유지하며 종료 시 원래 필드 색으로 돌아갑니다.
- 몬스터 위 HP바는 개별 현재 HP/최대 HP 비율을 표시합니다. 대형 몬스터의 스프라이트 크기를 따르고 실드에 막힌 공격은 HP바를 줄이지 않습니다. 사망·비활성화 시 숨깁니다.
- 액티브 1/2, 궁극기, 일반 공격, 패시브 칸을 클릭하면 해당 칸 위에 이름·설명·조건 툴팁을 표시합니다. 조준 취소, 캐릭터 선택 변경과 스테이지 퇴장 시 닫힙니다. 스킬/게이지 사용이 막혀도 설명을 볼 수 있습니다.

## 자동 검증

```bash
python Tools/MapEditorTests/run_tests.py
python Tools/MapEditorTests/validate_scenes.py
python Tools/PassiveTests/run_tests.py
python Tools/PassiveTests/validate_stage_ui.py
```

첫 번째 명령은 .NET SDK가 필요하며 `MAP_EDITOR_DOTNET`과 `MAP_EDITOR_CSC`로 경로를 지정할 수 있습니다. 런타임 소스를 UNITY_EDITOR 없이 컴파일한 뒤 에디터 소스와 함께 48개 API double 시나리오를 실행합니다. 맵 추가/삭제와 Undo, 웨이브 순서, 몬스터 배치와 큰 몬스터 실드, 단일 설정 원본, 중복 연결/ID 차단, 맵별 팔레트 격리, 공유 맵의 클리어 ID, 장애물/필드 로딩과 퇴장 정리를 검증합니다.

씬 검증은 Python 표준 라이브러리만 사용합니다. SampleScene, first, SampleScene_Tutorial의 Tilemap·버튼·웨이브·몬스터·프리팹 참조, 클리어 ID 0~29, 모든 몬스터의 점유 영역을 검사합니다. 1스테이지의 7개 웨이브와 ID 5, 5스테이지의 ID 1000도 확인합니다. PassiveTests는 기존 전투, 저장, 다중 칸/실드와 Hover에 더해 HUD·HP바·툴팁의 상태/위치 로직을 검증합니다. `validate_stage_ui.py`는 세 씬의 wave/enemy 텍스트와 다섯 스킬 클릭 이벤트 연결을 검사합니다.

이 검증은 Unity의 실제 임포트, 네이티브 직렬화, Undo 엔진과 Play Mode를 대신하지 않습니다.

## Unity에서 확인할 항목

- 씬을 열고 맵에디터에서 각 Tilemap의 버튼·몬스터 목록과 웨이브가 표시되는지 확인합니다.
- 목록과 배치를 수정한 뒤 Ctrl+Z/Ctrl+Y, 저장, 씬 재열기로 설정이 유지되는지 확인합니다.
- 1스테이지는 Wave 1~7이 실행되고, 5스테이지는 대형 몬스터가 생성되어야 합니다.
- 스테이지 간 재진입 시 선택한 맵과 몬스터만 활성화되고 이전 장애물/필드가 남지 않아야 합니다.
- 필요 진행도의 경계, 저장 슬롯 전환 후 버튼 표시, 공유 맵 버튼별 클리어 기록과 전투 후 시나리오를 확인합니다.
- wave/enemy 숫자, 필드 색상과 미리보기, 몬스터 HP바의 위치·비율, 각 스킬 칸 위 툴팁과 해상도 변경 시 위치를 확인합니다.
