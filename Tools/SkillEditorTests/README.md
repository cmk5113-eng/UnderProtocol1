# ROE의 기준은 스킬에디터 패턴

기본 공격·액티브·궁극기의 공격 범위와 칸별 피해·밀치기·필드는 `SkillList.roePattern`으로 결정한다.

- 숨겨진 전체 수치 `aoe`, `damage`, `pushDistance`와 구형 실행 경로를 제거했다.
- 실행 API는 스킬·시전자·조준 칸·회전만 받고, 외부 대상 목록이나 타일 값을 받지 않는다.
- 프리셋과 새 ROE 칸은 피해 1, 밀치기 거리 0으로 생성한다. 후속 편집은 선택한 ROE 칸에만 적용한다.
- 좌클릭은 피해 1→2→3→1, 우클릭은 칸 켜기/끄기를 유지한다.
- ROE를 비우면 기본 공격 범위를 자동으로 생성하지 않는다. 공격과 AP 소비 없이 조준을 종료한다. 빈 궁극기를 선택해도 게이지를 차감하지 않는다.
- 시전 직전에도 패턴을 다시 읽어서 오래된 미리보기의 칸이 실행과 생존 적 추가 공격에 쓰이지 않게 한다.

기존 에디터 패턴 29개는 그대로 보존했다. 구형 범위만 쓰던 에셋 23개는 기존 맨해튼 반경·피해·밀치기 수치를 명시적인 ROE 칸으로 옮겼다. 105개 스킬 에셋에서 구형 전체 ROE 수치가 제거됐는지 확인했다. 스킬의 GUID, 장착 연결, 시전 사거리와 효과 플래그는 유지한다.

## 자동 검사

설치된 .NET SDK로 실행한다. SDK가 PATH에 없으면 `PASSIVE_DOTNET`에 dotnet 실행 파일 경로를 지정할 수 있다.

```sh
python3 Tools/SkillEditorTests/run_tests.py
python3 Tools/PassiveTests/run_tests.py
```

에디터 검사는 실제 `SkillListEditor`를 컴파일하고 IMGUI 입력 대체 객체로 격자 좌·우클릭, 프리셋, 초기화 후 재표시를 확인한다. 전투 검사는 실제 전투 코드를 Unity API 대체 객체와 컴파일해 ROE·회전·실드·필드·패시브·저장·호버 동작을 확인한다. Unity의 에셋 임포트 및 화면 렌더링 검사를 대체하지 않는다.

## Unity에서 확인할 항목

1. 기존 기본 공격과 액티브·궁극기를 열어 ROE 모양과 칸별 값이 유지되는지 확인한다.
2. 같은 칸을 좌클릭 네 번 눌러 1→2→3→1을 확인하고, 우클릭으로 제거·추가한다. 프리셋의 새 칸은 피해 1로 시작한다.
3. 실제 전투에서 칸별 피해와 회전을 확인한다. ROE를 전부 지운 스킬을 선택하면 공격이나 AP 소비가 발생하지 않아야 한다.
